# Сквозные сценарии A–K

Дата: 25.10.2026. Проектное решение, если явно не указано иное.


| ID | Действия | Условие успешности |
|---|---|---|
| A | НК синхронизация/GTIN→выбор БМ | Один product без повторного ввода и с внешним provenance |
| B | Импорт→эмиссия→PDF→нанесение→отчёт→АТК | Ни один этап не завершён только по HTTP200 |
| C | Логист дважды передаёт накладную | Один task, правильный per-invoice состав, нет Excel/эмиссии |
| D | ПК сканирует, ТСД продолжает | Центральные сканы, актуальная проверка полного состава/количества |
| E | Отгрузка с чужим GTIN, затем корректная | Первый скан отклонён без TrueAPI; batch только по кнопке |
| F | Split, timeout и restart | Резерв не потерян, заказ не повторён, done после final reconcile |
| G | Повтор PDF/печать | Использован тот же payload; ни одного нового заказа/отчёта |
| H | Админ снимает scan permission | Активная сессия получает отказ без restart |
| I | Админ меняет правило | Новая операция использует новую версию; старая сохраняет snapshot |
| J | ТСД открывает любой чужой модуль | Базовый профиль видит только три раздела, API deny |
| K | Специалист работает со всеми операциями | Восстановление доступно; настройки/пользователи/секреты запрещены |

Отдельно: общий АТК из трёх накладных → три непересекающихся ожидаемых набора; трансформация → stale tasks и явное обновление.
Для неизвестного внешнего результата evidence важнее завершения красивого сценария.

## Дополнительные сценарии после объединения модулей (27.10.2026)

| ID | Действия | Условие успешности |
|---|---|---|
| L | Логист возвращает БМ → полный Excel → склад | Добавлены информационные строки; исходные маркированные PN/GTIN/количество сохранены, новой эмиссии нет |
| M | Перепечать с причиной, лимитом и контрольным сканом | Использован тот же payload/PDF; число подтверждений соответствует политике, лишние копии запрещены |
| N | Прямая печать → потеря ответа агента → сверка | Задание не выдаётся второй раз; неизвестный исход разбирается до повторной печати |
| O | Повреждённый UNIT → официальная перемаркировка | LK_REMARK подтверждён; старый КМ выведен по перемаркировке, новый введён; старый PDF недоступен |
| P | ФТС из ERP → квитанция → итоговая сверка | Подтверждены документ, декларация, связь АТК и статусы КМ; принятое HTTP200 не завершает сценарий |
| Q | Плановое обновление токенов → отключение делегата | Токены сохраняются зашифрованно, секреты не попадают в UI; отключённый делегат не обновляет доступ |
| R | Обращение с ТСД → карантин → разбор → снятие | Чужой сотрудник не видит обращение; ограничены только нужные действия и КМ, другие операции продолжаются |
| S | Карантин до выдачи печати → снятие → возобновление | Агент не получил PDF во время запрета; возобновлено то же задание, без дубля и изменения копий |
| T | Состояние системы → отзыв административного права | Показаны только локальные сведения без токенов; после отзыва API отказывает активной сессии |

Для пилота результаты фиксируют по [PILOT-RECORD.md](PILOT-RECORD.md).
Наличие сценария и успешный CI не означают его выполнение на настоящих подключениях.
