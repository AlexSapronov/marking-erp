# Техническая приёмка бизнес-цепочки

28.10.2026. Проверяется код MVP в изолированной PostgreSQL. Это не акт боевой
приёмки ЧЗ/СУЗ, НК, CryptoPro, принтера или ТСД. Развёртывание не выполнялось.

## Что изменилось в проверке

`tests/test_chain_acceptance_postgres.py` проходит связный процесс через реальные
HTTP-маршруты ERP, личные сессии, бизнес-проверки, PostgreSQL, очередь команд,
`dispatch_once` и `BusinessWorker.reconcile`. Состояния накладных, карточек,
бизнес-процессов и КМ не выставляются напрямую SQL-запросами.

Внешняя граница — `tests/chain_harness.py`. `httpx.MockTransport` перехватывает
весь HTTP клиентов интеграций; неизвестные пути отклоняются. Все credentials,
номера документов, ответы, квитанции и коды синтетические. НК ограничивает
частоту тем же кодом, что и обычный клиент. Зарегистрирован отдельный тестовый
подписант: job → CMS → receipt «не проверено» → проверка точных bytes закреплённым
RSA-сертификатом через OpenSSL → разрешение очереди. Это **не проверка ГОСТ,
CryptoPro, МЧД, цепочки доверия или отзыва продуктивного сертификата**.
Печатный агент проходит настоящий протокол выдачи PDF и приёма результата;
драйвер и физическая печать представлены синтетическим `spooled`.

Тестовый транспорт находится только в `tests/`. Режимов имитации и новых
способов обхода проверок в рабочее приложение не добавлено.

## Результаты связного сценария

Два сценария прошли локально. Конкретный SHA, итоговый полный CI и протокол
офлайн-установки/восстановления фиксируются в PR этого изменения.

| Участок | Что проверено в связном прогоне |
|---|---|
| НК — первая входная точка | Карточка с текстовым PN `00123-A` → синтетический ответ схемы через клиент НК → выделение GTIN → сохранение → модерация → документ публикации → CMS → подписанная публикация → чтение опубликованного статуса и общий справочник |
| Накладная БМ | Создание и проверка состава по подтверждённым PN/GTIN/полному ТН ВЭД; повтор старта возвращает тот же процесс |
| Эмиссия | Подпись заказа → СУЗ → проверка готовности → получение КМ → запись реестра → сохранённые PDF/ZIP; прямой подстановки `labels_ready` нет |
| Автопечать | Одно явное намерение → очередь точного комплекта → отдельный агент → проверка bytes PDF и SHA-256 → результат `spooled`; повтор результата не выдаёт второй экземпляр |
| Перепечать | Причина и лимит копий; подтверждение печати и полный контрольный скан; повтор одного запроса не добавляет экземпляр или эмиссию |
| Нанесение | До передачи актуальных этикеток подтверждение блокируется; после передачи — нанесение, отчёт, подпись и квитанция |
| Отклонение отчёта | Первая попытка отклоняется синтетическим СУЗ; документ остаётся отклонённым; явная повторная попытка после снятия синтетического отказа подтверждается отдельной квитанцией и APPLIED |
| АТК | Полная партия поставщика → документ с подписью → независимый readback parent → сохранённый Excel → явная передача поставщику |
| ФТС / ввод в оборот | Досье → LP_FTS_INTRODUCE → успешная квитанция; APPLIED после квитанции ещё блокирует успех; только последующий INTRODUCED переводит пакет в подтверждённый ввод |
| Возврат в БМ | Логист возвращает тот же документ; полный Excel добавляет немаркируемую строку; повтор commit не повторяет эмиссию и сохраняет маркированную часть |
| Приёмка | Точный состав КМ, запрет дубликата, проверка владельца/статуса/фасовки; чужой владелец блокирует сверку и закрытие; исправленная сверка разрешает закрытие |
| Повреждённый КМ после приёмки | Отдельный REMARK → эмиссия нового КМ → этикетка → нанесение и отчёт → LK_REMARK → WRITTEN_OFF/REMARK_RETIRED старого и INTRODUCED нового; старая перепечать запрещена |
| Отгрузка | В ожидаемый состав попадает подтверждённая замена; полный скан, проверка ЧЗ и закрытие; экспорт содержит немаркируемые строки из полного Excel |
| Потеря ответа скана | Повтор успешно сохранённого request_id после закрытия возвращает старый результат без второй записи |
| Завершение и архив | Все этапы разрешают завершение логистом; повтор завершения идемпотентен; администратор архивирует обе заполненные накладные; история, замена и квитанции сохраняются |
| Потеря ответа заказа | Внешняя граница принимает заказ и теряет ответ; ERP сохраняет unknown; повторные проходы очереди и ручное resume не создают второй заказ и КМ |

## Что остаётся проверить Александру в реальных условиях

- Фактические ответы НК: обязательные поля радиокомпонентов, точный PN/GTIN,
  публикация, модерация, ограничения частоты и массовые файлы предприятия.
- Полномочия ЧЗ/СУЗ, товарная группа, OMS, договор, токены, цены/лимиты и квитанции
  реальной эмиссии, отчёта, АТК, трансформации, ввода и перемаркировки.
- ГОСТ-подпись на целевом Windows-ПК: CryptoPro, сертификат/МЧД, закреплённый
  сертификат, доверие, отзыв и работа под обычной пользовательской учётной записью.
- Принтер: драйвер, SumatraPDF, формат 58×40 и масштаб 100%, реальный отпечаток и
  его читаемость; неизвестный результат сверяется до любого нового экземпляра.
- MERTECH S55/S45: AIM/GS/Enter, полный криптохвост, раскладка, сон/reconnect,
  две одновременные сессии и физическая сверка реальной поставки.
- Реальный остаток исходного КМ после разделения; реальные статусы предыдущего
  и нового КМ после перемаркировки; совпадение ожидаемого состава поставки.
- Собственная целевая среда, backup/restore и пользовательская приёмка по ролям.
  ДТ в таможню подаёт импортёр/брокер; подача документа в ЧЗ не заменяет её.

новые боевые операции от имени пользователя и не означает готовность всех
интеграций без подключения и приёмки оборудования.
