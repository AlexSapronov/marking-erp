# Аудит склада

Дата: 25.10.2026. Проектное решение, если явно не указано иное.


Реализация: warehouse_store.py, warehouse_service.py, warehouse_excel.py, datamatrix.py, trueapi.py, warehouse_routes.py.
Положительные свойства: точное сравнение полного нормализованного КМ в приёмке; локальный whitelist GTIN при добавлении скана;
UNIQUE(document_id,cis); результат привязан к версии сканов; новые сканы делают старую проверку неактуальной;
True API вызывается пакетно при «Проверить», quantityInPack учитывается для отгрузки; дополнительная табличная часть немаркированных строк.
234 Python-теста прошли. Это не проверка нового PostgreSQL и реального Android.

| Область | Итог | Перенос |
|---|---|---|
| Сканирование и запрет чужого GTIN | PASS локальных тестов | Переиспользовать с actor/device/request_id |
| Сохранность полного КМ | PASS выбранных тестов | Дополнить общим corpus для трёх парсеров |
| Сверка приёмки по полным КМ | PASS для равенства байтов; FAIL количества W-002 | Исправить предикат и входные инварианты |
| Проверка/завершение при новых сканах | PASS текущих тестов | PostgreSQL optimistic revision + row lock |
| Доступ сотрудников | FAIL W-001 | Новые общие dependencies |
| Передача логистом без Excel | Отсутствует | Новый application service одной БД |
| PN из model / fallback каталога | Реализован | Общий справочник с provenance, запрет выдуманного PN |
| Выгрузка и защита формул | Имеются проверки в тестах | Дополнить Unicode/числовыми ячейками и полными кодами |

Не переносить модель строк с PRIMARY KEY(document_id,gtin) как общий каталог:
целевая ERP допускает разные PN для одного GTIN. Для складского баланса хранить и строку-источник, и группировку GTIN.
