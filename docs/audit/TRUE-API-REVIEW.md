## Новый дефект формата разделения S-004

S12 описывает пару: новый КМ с переменной характеристикой, ASCII30, исходный КМ с кодом проверки без переменной характеристики.
S13 связывает неверную композицию с ошибкой7846.
Исходный km_split/codes.py:85–89 соединяет new.full+RS+source.full. Если исходная физическая этикетка содержит AI30, он попадает во вторую часть отчёта.
Локальная проба передала исходный AI30=100 и получила его же во второй части. Нужное для API представление не сформировано.

Исправление в будущей ERP: хранить original_full неизменным, отдельно строить source_report_payload без переменной характеристики,
сохраняя КИ и криптографическую часть побайтно. Это преобразование транспортного представления, а не правка исходной этикетки.
Не обрезать строку поиском подстроки30: она может встретиться в serial/crypto. Нужен строгий parser подтверждённого шаблона.
Регрессии: оба шаблона36/37, source с AI30 и без, repeated split, 30/91/92 в serial/crypto, RS/GS на нужных границах.
