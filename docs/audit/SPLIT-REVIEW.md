# Аудит разделения

Дата: 25.10.2026. Проектное решение, если явно не указано иное.


Реализация: km_split/service.py, clients.py, codes.py, labels.py и main.py.
Переиспользовать request_id+fingerprint, транзакционный резерв, запрет автоповтора неизвестной отправки,
сохранение полученного кода до генерации PDF, различение receipt resultDocId/sourceDocId и повторную выдачу PDF без заказа.

| Область | Итог |
|---|---|
| Локальный резерв и идемпотентность | Реализованы; основной workflow-набор здесь не исполнен из-за zxingcpp |
| Проверка владельца, INTRODUCED и quantityInPack | Есть в коде |
| UNIT, statusEx и переменная характеристика НК | FAIL S-002 |
| report SUCCESS и полные успешные квитанции | Есть проверка |
| Итоговое внешнее состояние нового/исходного КМ | FAIL S-003 |
| Настройки, чужие операции, скачивание PDF | FAIL S-001 |
| Точный JSON DIVISIONMARK и RS-композиция | UNVERIFIED, нужен API СУЗ и контрактные примеры |
| Печать PDF | Генерация есть; физическая печать и декодирование здесь не подтверждены |

С06 допускает повторное разделение и различает единичную часть и сумму нескольких частей.
Существующая реализация оставляет минимум одну единицу; это более узкий MVP. Поддержку полного разбиения несколькими частями проектировать отдельно,
не ослабляя проверку каждой части. Первая версия ERP может сохранить операцию «отделить часть» с явным описанием ограничения.
В ERP прежде всего сохранить остаток и неизвестность, затем разрешать новые заказы.
