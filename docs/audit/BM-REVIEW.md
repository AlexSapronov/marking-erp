# Аудит БМ и АТК

Дата: 25.10.2026. Проектное решение, если явно не указано иное.


Исследованы marking_bm/{service,worker,gateway,db,excel,codes,labels,auth}.py и main.py.
Сохранять: объединение строк Excel, supplier batches, происхождение кодов, запрет PDF до получения полного количества,
отчёт на накладную, АТК по поставщику и полному ТН ВЭД, версии трансформаций, остановку с сохранением позднего ответа.
Gateway различает неопределённость мутации, проверяет ID ответов и внешние статусы; worker восстанавливает dispatching в unknown.
Это хорошая исходная семантика, но не доказательство актуальности JSON-контракта СУЗ.

| Область | Итог / решение |
|---|---|
| Excel PN/GTIN/количество | Сохранить importer и предупреждения; общий products lookup |
| Эмиссия / частичная выдача | Сохранить order→buffers→fetch и recovery block; контракт UNVERIFIED |
| AI30 / этикетка | Строгий parser СУЗ и добавление количества отдельно; не применять scanner-normalization к ответу эмиссии |
| Нанесение → АТК | Есть квитанции и сверка; переносить как guarded state transitions |
| Трансформации | Есть версии и ограничение reuse; новое permission prepare/approve |
| Архив / stop | Есть остановка и admin restore; ERP по ТЗ допускает также специалиста |
| Логист | Общий реестр/скачивание есть; логист→склад и ФТС требуют нового процесса |
| Авторизация | Проверяются role/owner/files, но вход по имени FAIL A-001 |
| Worker | Однопроцессный lock и SQLite: Q-001, нужна новая реализация claim |
