По поручению пользователя от 26.10.2026 продолжается реализация локальных бизнес-функций и UI/UX всех четырёх проектов. Номера этапов этой таблицы не являются номерами фактических GitHub PR. Неподтверждённые внешние отправки остаются закрыты по CHECKPOINT; интерфейс и синтетические тесты не подменяют контролируемый пилот. Текущее покрытие — в DELIVERY-STATUS.md.
Часть PR может потребовать разделения; не объединять весь продукт в один merge.

## Срез после основного объединения

Основной функциональный срез этапов 03–18 реализован в main, включая PR #27; фактические ограничения и проверка боевого процесса приведены в DELIVERY-STATUS.md. Этап 19 реализован в PR #28 и включает центр проблем и локальный карантин, без внешних изменяющих API. Для этапа 20 добавлены локальная диагностика подключений/очередей, инструкции по ролям и комплект приёмки в офлайн-релизе. Его завершение требует приёмки оборудования и контролируемого пилота после отдельного решения о развёртывании; автоматические проверки не заменяют эти действия.

Дополнение этапа 10: рабочий список НК скрывает черновики с точным опубликованным
PN по умолчанию; фильтр возвращает их в список и Excel. Скрытие не меняет данные
или синхронизацию и не применяется к похожим PN.

Дополнение этапа 10: партия импорта НК хранит исходный XLSX, точные связи всех строк
с карточками и выгружает книгу с GTIN/результатом; повтор подтверждения безопасен,
различающиеся данные не схлопываются по одному PN. Старые партии сохраняют прежний экспорт.

Дополнение этапа 14: локальное сравнение полного ожидаемого КМ и пакетная складская
кнопка «Проверить»; внешние сведения не запрашиваются при каждом скане. Результат
привязан к составу, политике и сроку, сбрасывается после изменений и restore.


Контроль SPEC §14.3 дополнен запретом пересечения КМ разных открытых накладных
одной организации при передаче, сканировании, сверке, закрытии и возврате в работу.
Приёмка и отгрузка одного источника совместимы; закрытие/отмена освобождают код,
история сохраняется. Миграция 0016 добавляет индексы без изменения старого состава.

Дополнение SPEC §15.5: резервный Excel склада с отдельными preview/commit,
неизменяемым исходником, полными ожидаемыми КМ, причиной и назначениями.
Типизированный источник Excel не создаёт фиктивный документ БМ и не запускает
эмиссию. Миграция 0017 сохраняет существующие источники БМ и их ревизии.

### Продолжение после PR #34: допуск разделения по НК

Перед созданием разделения и непосредственно перед отправкой `split.order`
ERP читает актуальную карточку через существующий `/v3/feed-product`.
Атрибут `24003` должен однозначно подтверждать `КОЛИЧЕСТВО`; отсутствие,
противоречие или другой тип останавливают заказ до эмиссии. В документе
сохраняются ID карточки, время проверки и SHA-256 ответа. Повтор существующего
запроса возвращает документ без новой проверки/эмиссии. Ошибка чтения перед
отправкой переводит операцию в `blocked`, а не в неизвестный результат отправки.
Нужен действующий ключ НК той же организации. Живой пилот остаётся отдельным этапом.

Сверены актуальные основные ветки рабочих проектов:
- `marking-bm` `7ab87280`: подтверждения действий, точные названия отчётов СУЗ
  и передачи логистам; предыдущие изменения — актуальность ATK/RESULT,
  пагинация/сортировка и явный выбор между страницами. Учесть в этапе общего UI.
- `nk-manager` `77ec562e`: стабильные персональные сессии и пароли, отдельное
  разрешение loopback Host для подписанта через SSH-туннель. Не переносить
  исключение Host без отдельного транспортного сценария ERP.
- `gis-trueapi` `503b87d4`: проверка GTIN при складском сканировании;
  соответствующая проверка в ERP уже есть, дополнительно сверяются полные КМ.
- `km-split` `19c8329a`: GS-разделители и регенерация старого кэша этикеток;
  генератор ERP уже кодирует GS как ASCII 29. Чужие кеши PDF не импортируются.
- База ERP: `e917e0ad` (PR #34). Развёртывание отложено по указанию заказчика.
