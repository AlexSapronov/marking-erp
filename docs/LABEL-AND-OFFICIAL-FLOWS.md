# Перепечать, замена КМ, ФТС и автоматизация доступа

Реализация добавлена в ERP; производственное развёртывание этим изменением не выполняется.
Контракты сверены 27.10.2026 с официальной [True API v747.0 от 21.10.2026](https://docs.crpt.ru/gismt/True_API/): §§1.5, 4.1.4.8, 4.1.19, 11.1. Используется группа `radio`.

## Перепечать

Сотрудник находит сохранённый КМ, указывает причину и число копий. Сервер сохраняет снимок правил организации: обязательность причины, максимум копий, необходимость контрольного сканирования. Одновременно допускается одно незавершённое задание для одного КМ. Повтор запроса с прежним request_id возвращает то же задание.

Этикетка берётся из последнего сохранённого ZIP без восстановления криптохвоста или генерации нового КМ. Проверяются текущие PN, количество и хеш полного payload. После подтверждения физической печати сотрудник сканирует каждый экземпляр, если это предусмотрено сохранёнными правилами. Контроль сравнивает полный КМ, включая криптохвост и AI30. Политика не изменяется задним числом. Скан не способен доказать, что разные экземпляры действительно физически различаются: это ответственность оператора. PDF и драйвер принтера не являются DRM; сервер ограничивает свои задания, но не может запретить дополнительные копии вне ERP.

Отмена допускается до отправки на принтер. Отозванные права, архив, возврат КМ в пул, изменение payload или официальная замена блокируют использование прежнего PDF. Факты и причины сохраняются в аудите.

## Прямая печать

Агент Windows получает задание по HTTPS, проверяет SHA-256 сохранённого PDF и отправляет его на конкретный разрешённый принтер с масштабом 100% и заданным количеством экземпляров. Поддерживается печать исходного комплекта и отдельной перепечати. Повторная печать уже отправленного комплекта требует отдельных заданий перепечати.

Настройка выполняется администратором сервера после установки обновления:

```text
marking-erp register-printer --organization-id ORG_UUID --name Warehouse --printer-name "Exact Windows Printer Name"
```

Команда выдаёт отдельный bearer-токен один раз. На Windows запустить:

```powershell
.\Start-ErpPrinter.ps1 -BaseUrl https://erp.example -SumatraPath 'C:\Program Files\SumatraPDF\SumatraPDF.exe'
```

Нужен официальный SumatraPDF с действительной Authenticode-подписью и установленный принтер с бумагой 58×40 мм. Агент не скачивает исполняемые файлы, не выполняет произвольные команды из ERP, не открывает локальный HTTP-порт. Он не требует прав администратора Windows для работы с уже установленным доступным принтером. Токен запрашивается скрытым вводом. Отзыв: `marking-erp revoke-printer --device-id DEVICE_UUID`. После восстановления резервной копии принтеры отключены, старые очереди не переотправляются, авторизационные challenges просрочены, внешние записи и автоматическое обновление токенов выключены. Нужно отдельно сверить операции и зарегистрировать устройства.

Задание выдаётся агенту один раз. Локальная отметка фиксируется до вызова печати. При обрыве соединения, падении агента или непонятном результате сервер не повторяет печать. Прочие задания этого принтера ожидают сверки. Администратор проверяет принтер/очередь и явно фиксирует результат через кнопку сверки в окне задания. Даже успешный выход PDF-рендерера означает передачу на печать, а не доказательство физического отпечатка; это подтверждает сотрудник. После подтверждённой отмены перепечати нужно отменить старый запрос и создать новый.

## Официальная перемаркировка

Отдельное рабочее место «Официальная перемаркировка», причина `KM_SPOILED` (повреждение/утрата этикетки), замена единицы товара `UNIT`. Исходный КМ должен быть известен ERP, принадлежать организации, находиться в обороте без особого состояния ; новый КМ не должен входить в агрегат. Количество проверяется по ЧЗ. Не допускается параллельное разделение/замена того же КМ.

1. Подтвердить причину и платный заказ одного нового КМ с типом эмиссии `REMARK`.
2. Получить КМ и сохранённую этикетку с тем же GTIN/PN/количеством, напечатать и нанести её.
3. Подписать и отправить отчёт о нанесении. Дождаться реального статуса `APPLIED` нового КМ.
4. Подтвердить дату и подать отдельный подписанный документ `LK_REMARK`, связывающий `last_uin` и `new_uin`.
5. Дождаться успешной квитанции, состояния нового КМ `INTRODUCED` и предыдущего `WRITTEN_OFF`/`REMARK_RETIRED`.

До последнего шага ERP не объявляет замену завершённой. После подтверждения старые этикетки блокируются, связь сохраняется в неизменяемом реестре замен, документе и квитанции. Новые складские задания используют актуальный КМ по цепочке подтверждённых замен, исторические отчёты/АТК/сверки не переписываются. При активной складской сверке замена заблокирована: сначала её нужно завершить или отменить. Сценарии розничных возвратов, изменения описания товара, неизвестного исходного КМ и замены агрегатов этим процессом не охватываются. Известный отказ допускает явный повтор отчёта/официального документа после исправления причины; неизвестный результат повторно не отправляется.

## Импорт с ФТС

Подготовленный пакет содержит номера АТК, точный состав, декларацию и дату. Кнопка «Подписать и подать в ЧЗ» ставит в устойчивую очередь `LP_FTS_INTRODUCE`. Это подача уведомления о вводе в оборот в ЧЗ, а не отправка таможенной декларации в систему ФТС. Декларирование остаётся процедурой импортёра/брокера.

Проверяются формат номера ДТ, соответствие даты в номере, владелец, статусы и актуальный состав АТК. Для товаров закрытого сегмента необходимо явно указать признак и трёхзначный код страны по ОКСМ; вложения содержат ТН ВЭД и страну производства. Разрешительные сведения из досье не превращаются в выдуманные структурированные поля: проверки действующей документации выполняет ЧЗ на основании ранее переданных данных/НК. Если они отсутствуют, документ может быть отклонён и требует исправления исходных сведений.

Отправка использует точные подписанные байты JSON, `MANUAL` и отдельный тип документа. Ни HTTP 200, ни ID документа, ни промежуточный `CHECKED_OK` сами по себе не означают ввод в оборот. ERP проверяет связь квитанции с декларацией и АТК, затем `INTRODUCED` всех КМ с сохранением состава. Ожидание ФТС может продолжаться после принятия документа. Подача через ЛК с последующей строгой проверкой оставлена для ранее созданных пакетов и ручного резервного процесса. При неизвестном исходе автоматическая повторная подача запрещена.

## Автообновление ЧЗ/СУЗ

В «Подключениях» администратор сохраняет OMS Connection и включает автоматическое обновление токенов. Для существующих настроек ручные токены продолжают работать. Автообновление — отдельное делегированное полномочие, оно не включает платную эмиссию или юридическую подачу документов без соответствующего задания.

Зарегистрировать подписант с дополнительными разрешёнными видами `auth.true` и `auth.oms`, затем явно зарегистрировать доверие к Windows-верификатору. Использовать текущую команду `register-signer` с нужными `--kind` (включая бизнес-операции, которые будет подписывать это устройство). Нельзя расширять существующий bearer-токен через браузер; требуется регистрация/отзыв на сервере.

```powershell
.\Start-ErpSigner.ps1 -BaseUrl https://erp.example -Thumbprint CERT_SHA1 -EnableTokenRefresh
```

ERP получает пару uuid/data из `/auth/key`. Доверенный Windows-агент проверяет точные байты и закреплённый сертификат, формирует присоединённую CAdES-подпись и проверяет её/цепочку через CryptoPro. Сервер обменивает подпись на UUID-токен True API (`unitedToken=true`, поле `uuidToken`) либо СУЗ (`/auth/simpleSignIn/{omsConnection}`, поле `token`). Секреты сохраняются зашифрованными и не возвращаются сотрудникам/агенту. Обычная полученная CMS без регистрации доверенного верификатора не считается достаточным доказательством.

Плановое обновление — не позднее 8 часов, для True API учитывается более ранний `expireDate`. Просроченный challenge не переиспользуется, ошибки имеют ограниченную частоту повторных запросов авторизации. Кнопка обновления запрашивает новый challenge без ручного копирования токена. Отзыв подписанта/доверия/прав администратора блокирует обновление. Без вставленного токена УКЭП и работающего Windows-подписанта обновление не выполнится; статус виден в подключениях. PIN/закрытый ключ остаются в CryptoPro/Рутокен.

## Проверка на целевой среде

Кодовые проверки используют PostgreSQL и синтетические внешние ответы. Они не подтверждают приём документов в продуктивном ЧЗ или печать на конкретной модели. После будущего развёртывания нужны проверка сертификата/МЧД/цепочки, разрешений ЧЗ/СУЗ, один согласованный документ импорта, одна замена и проверка отпечатка сканером S55/S45. До этого боевую приёмку объявлять завершённой нельзя.
