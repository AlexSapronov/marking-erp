# Фактическая готовность единой ERP

Дата: 26.10.2026. Это состояние реализации, а не план или обещание готовности.

| Исходный проект / процесс | Что доступно в ERP | Что ещё требуется |
|---|---|---|
| Общая платформа | PostgreSQL, шесть групп, личный вход/MFA, редакторы пользователей/прав/правил, профиль/сеансы, аудит, диагностика, backup/restore | Целевой deployment и эксплуатационный пилот |
| marking-bm: подготовка | Реестр накладных, ручной состав, Excel с mapping/preview, версии, локальная проверка, стоп/архив/возврат | Справочник поставщиков/алиасов и batch-сценарии |
| marking-bm: маркировка и АТК | Общий реестр payload/файлов и очередь — основание для модуля | СУЗ: эмиссия/получение, применение/отчёты, АТК/трансформации, логистика и конечные файлы |
| nk-manager | CLI чтения и захвата/разбора пилота; read-only API подтверждённых товаров | UI карточек/шаблонов/массовых действий, проверенная синхронизация, создание/GTIN/модерация/публикация и bulk Excel |
| gis-trueapi | Назначенные задания приёмки/отгрузки из накладных БМ, передача логист→склад, физические сканы/количества, дубли/чужой GTIN, удаление скана, закрытие/возврат/отмена, Excel закрытой отгрузки, UI ПК/ТСД | Внешняя проверка ЧЗ/владельца, сверка ожидаемого списка конкретных КМ, приёмка немаркированных строк, пилот сканера |
| km-split | Проверенный локальный formatter, renderer и очередь | Preflight источника, резерв, эмиссия/получение/нанесение/отчёт и итоговая сверка; рабочий экран |
| Подпись и устройства | Протокол очереди подписанта; UI адаптирован к узким экранам | Доверенная проверка ГОСТ, Windows/CryptoPro/Рутокен, реальные S55/S45 и принтер |

UI/UX существует для реализованных функций. Он не является завершённым интерфейсом
всех четырёх проектов. [Складской MVP и сценарий презентации](MVP-WAREHOUSE.md) описывают доступный физический процесс.
Карточки «Готовится к запуску» на главной — ограничения,
а не готовые бизнес-модули. ERP пока не заменяет четыре рабочих приложения.

Для продуктивных внешних действий остаётся CHECKPOINT: точные версии контрактов,
безопасные запросы/ответы, ограничения и recovery, проверка реального пилота.
Изготовление интерфейса или синтетический CI не подтверждают успешную эмиссию,
операцию ЧЗ или юридическую пригодность подписи. Токены и ПИН нельзя добавлять
в Git или публичные артефакты. Дальнейшая разработка локальных бизнес-сценариев
разрешена поручением пользователя; включение внешних операций требует фактов,
а не снятия блокеров одной правкой флага.
