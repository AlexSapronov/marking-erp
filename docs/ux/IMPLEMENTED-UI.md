# Реализованный интерфейс

Этот срез добавляет рабочий интерфейс к PostgreSQL API личного доступа. После настройки первого администратора по AUTHENTICATION.md откройте ERP_PUBLIC_URL. Нужны миграции, seed и настроенный ключ шифрования MFA. Демопользователей, начального пароля и отдельной публичной регистрации нет.

## Доступные действия

- `/` и `/login`: личный логин, пароль, TOTP; ошибки, ограничение попыток и завершение сессии.
- `/`: оболочка шести групп, организации текущего пользователя, настоящее административное действие управления пользователями. Карточки бизнес-модулей явно отмечены «Готовится к запуску» и не запускают операции.
- `/profile`: группа и организации, смена собственного пароля, выход на всех устройствах, подтверждение административного доступа.
- `/users`: список в пределах организаций администратора, поиск, фильтры группы/статуса, страницы по 25; создание, изменение имени/группы/организаций/статуса; сброс пароля, замена TOTP и отзыв сессий. Группы фиксированные, редактора permissions нет.

У пользователя ТСД на главной только три будущих складских сценария: приёмка, проверка КМ, отгрузка. Самих складских операций в этом срезе нет. Оболочка рассчитана на ширину от 320 px. Светлая/тёмная тема сохраняется локально; пароли, MFA и сессии в localStorage не сохраняются.

Серверные данные вставляются как текст. Cookie HttpOnly, CSRF и проверка Origin остаются на сервере. Статические HTML/JS не содержат пользовательских данных и доступны до входа. Все списки и изменения защищены серверным API; скрытие меню не заменяет авторизацию. Сессия обновляется каждые 30 секунд и при возвращении фокуса: отзыв права скрывает меню, закрывает административные формы; API отказывает сразу.

При истечении административных 5 минут нужно подтвердить пароль и следующий неиспользованный код TOTP. Мутация автоматически не повторяется. При потере сети неизвестный результат также не повторяется автоматически: сначала обновите список и проверьте фактическое состояние. Конфликт auth_version требует перечитать список. Последний администратор защищён в БД/API.

Для TOTP администратор явно создаёт/показывает ключ, передаёт его владельцу доверенным способом и вводит проверочный код. QR-кода и восстановления MFA пока нет. Закрытие формы очищает поля секретов. История административных изменений пишется сервером в audit; просмотр метаданных доступен отдельно в журнале аудита с правом audit.view, свежим MFA и глобальным доступом.

## Проверки

`pip install -e '.[test,browser]'`, `python -m playwright install --with-deps chromium`. Указать отдельную тестовую PostgreSQL через ERP_TEST_DATABASE_URL, выставить ERP_BROWSER_TESTS=1 и выполнить `python -m pytest -q`. На CI оба параметра обязательны; отсутствие БД/браузера не превращает проверки в успешные skips.

Браузер запускает настоящий Uvicorn и работает с изолированной схемой PostgreSQL: вход шести групп, мобильные 320 px, обе темы, создание/изменение/отзыв, смена собственного пароля, повторный MFA, отзыв permission в активной сессии, безопасный вывод серверных строк и разрыв сети. Ответы API не подменяются. Тестовые организации и ключи синтетические, существуют только в тестовой схеме.

GitHub Actions сохраняет PNG в артефакте `browser-screenshots` на 14 дней, включая снимки ошибок; JSON рядом содержит SHA, viewport и путь. Поля паролей и TOTP маскируются на снимках. Локальные проверки без PostgreSQL не заменяют этот прогон. Продуктивные НК/СУЗ/True API не вызываются.
# Дополнение: состояние системы

Доступен административный /system: ручное обновление десяти проверок инфраструктуры,
SHA/схема/время и отдельные ограничения подключений. Светлая/тёмная тема и узкий экран;
свежее MFA, global org-scope, очистка отчёта при ошибке/отзыве права.
Подробнее: [SYSTEM-STATUS](../architecture/SYSTEM-STATUS.md).



## Журнал аудита

`/audit`: фильтры по событию, UUID исполнителя и периоду, страницы по 25 событий,
пустое состояние и ручное обновление. Детали скрыты; неизвестные типы не раскрывают
сырые поля. Ошибка/MFA очищают строки. На 390 px таблица прокручивается внутри
панели. [Контракт и ограничения](../architecture/AUDIT-VIEW.md).


## Собственные входы

В профиле всех шести групп показываются до 20 действующих входов и общее количество.
Текущий вход отмечен первым. Можно завершить остальные входы с подтверждением,
сохранив текущий; отмена не выполняет запрос. Старый список очищается при ошибке,
результат команды после потери связи проверяется обновлением.
[Поведение и ограничения](../architecture/OWN-SESSIONS.md).
