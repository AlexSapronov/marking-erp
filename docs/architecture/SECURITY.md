# Модель доступа и доверия

Дата: 25.10.2026. Проектное решение, если явно не указано иное.


Начальный безопасный вариант: личные логин/пароль с scrypt/Argon2, серверные отзываемые сессии; администраторам MFA и повторный вход для критических настроек.
OIDC корпоративного IdP — предпочтительное развитие после подтверждения инфраструктуры.
ТСД входит личной учётной записью либо получает управляемую привязку устройства со сроком и отзывом; привязка не отменяет permissions.
Пользователь имеет одну основную группу и явный список организаций. own/assigned/all фильтруется в SQL, а не после выдачи данных.
Файл наследует scope связанного документа; UUID не является разрешением. Background-команда проверяет сохранённый actor и актуальный доступ перед отправкой.
HttpOnly+Secure+SameSite, CSRF на мутациях, CSP, escaping, rate limits, streaming upload limits и проверка содержимого Excel/ZIP.
Выгрузка строк как literal, защита =,+,-,@/управляющих префиксов; GTIN не превращается в число.
Секреты вне Git, не в ответах/логах. Полные КМ показывать только в разрешённом контексте; аудит не пишет crypto payload целиком.
Админ не может отключить идемпотентность, достоверность внешнего успеха, целостность КМ и количественные инварианты.
Последний действующий администратор не может снять себе все права или удалить единственный путь восстановления.
Закрытая сеть и kiosk launcher не заменяют серверную авторизацию.
