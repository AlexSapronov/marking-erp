# Сквозные процессы и состояния

Дата: 25.10.2026. Проектное решение, если явно не указано иное.


НК: local draft → saved remotely → moderation → awaiting_signature → published; каждое внешнее состояние с checked_at.
БМ: draft → validated → emission_pending → codes_partial → labels_ready → applied_confirmed → report_pending → reported → atk_pending → logistics_ready.
Ошибки и unknown — отдельные причины блокировки, а не успешные этапы. Сумма полученных КМ должна совпасть с подтверждённым заказом до PDF.
Supplier batch ждёт свои накладные; ошибка другого поставщика не блокирует независимый batch.
Трансформация: БМ готовит diff, специалист/администратор подтверждает; внешний успех создаёт новую immutable atk_version.

## БМ → Логист → Склад

Логист открывает подтверждённую накладную и «Передать в приёмку».
Сервис читает подтверждённые allocation+ATK версии; каждому исходному документу создаёт отдельное задание.
Общий АТК нескольких накладных не копируется целиком в каждое задание. Нужен origin line для каждого КМ.
Передача атомарна, без Excel, эмиссии и изменения ЧЗ; повтор возвращает тот же task_id.
Задание хранит source_revision, immutable expected payload versions/quantities и composition hash.
Если подтверждённая трансформация меняет состав — task получает stale_source, проверка/complete блокируются.
Явное «Обновить состав» показывает diff; старая версия и сканы сохраняются, совпавшие сканы переносятся с provenance, остальные становятся расхождением.
Закрытую приёмку не переписывать: новая версия требует разбора и нового задания/документа корректировки.

Склад: assigned → scanning → checking → discrepancies/ready_to_complete → completed.
Приёмка сверяет точный full payload, количество по строкам и полные множества; отгрузка дополнительно проверяет актуальные внешние факты пакетно.
Логист получает expected/scanned/accepted/missing/extra/problem counts и количества отдельно.
Закрытие накладной — отдельная команда после обязательных складских и логистических этапов; передача сама не закрывает накладную.

Stop: подтверждение номера+причины, остановка новых dispatch и безопасная отмена ожидающих заданий.
Уже отправленные операции остаются в reconcile; поздние ответы сохраняются. Локальная остановка не отменяет ЧЗ.
Restore: permission специалиста/админа, проверка pending/unknown/необратимых фактов, новая ревизия; не перезапускать автоматически расходующие операции.

Split: scan→external preflight→reserve→issue→receive→PDF→confirm_application→report→receipt→final_reconcile→done.
Reprint: find saved payload→reason→preview→PDF/print job→optional control scan; ноль новых заказов и отчётов ЧЗ.
ФТС и официальная перемаркировка: подготовка модели/интерфейса допустима; отправка заблокирована до подтверждения контрактов.
