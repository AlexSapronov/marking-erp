# Первый инфраструктурный срез

Реализованы только PostgreSQL, миграция core, seed шести групп/81 permission и два health endpoint.
Пользовательского рабочего места, входа, API документов и подключений ЦРПТ пока нет. Ready подтверждает схему БД, а не готовность бизнес-процессов.

## Запуск из чистой БД

Python3.12+, подготовленная PostgreSQL16+, отдельная пустая БД и роль с правом создания таблиц/функций.
Runtime-роль для дальнейшей эксплуатации должна быть отделена от миграционной роли; текущий срез предназначен для разработки.

```bash
python -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
# Установите ERP_DATABASE_URL через защищённое окружение, см. .env.example.
# Приложение не загружает .env автоматически и не имеет встроенного пароля БД.
.venv/bin/python -m marking_erp.cli migrate
.venv/bin/python -m marking_erp.cli seed
.venv/bin/python -m uvicorn marking_erp.web:create_app --factory --host 127.0.0.1 --port 8000
```

`GET /health/live` проверяет процесс. `GET /health/ready` возвращает503 при недоступной БД, отсутствии миграции или несовпадении версии схемы.
DSN и сообщения драйвера не возвращаются клиенту. Сам запуск API не создаёт таблицы и не сбрасывает права.
Seed выполняется один раз, сериализован PostgreSQL advisory lock; повторный запуск не восстанавливает отозванные/удалённые grants.
Первый администратор и личные пароли будут добавлены следующим срезом авторизации; сейчас users остаётся пустой.

## Проверки

```bash
# Только отдельная тестовая БД; тесты создают и удаляют собственную уникальную схему.
ERP_TEST_DATABASE_URL='<DSN тестовой БД>' .venv/bin/python -m pytest -q
```

Без тестовой БД локальные PostgreSQL-тесты пропускаются с явным сообщением; в CI отсутствие DSN считается ошибкой.
GitHub Actions поднимает PostgreSQL16 и проверяет clean install, повторный/конкурентный seed, constraints,
неизменяемый аудит, запрет административных прав специалисту, schema drift и downgrade/upgrade.
Полный production backup/restore пока не реализован и не заменяется тестом downgrade.

Миграция поставляется внутри Python-пакета; обычная wheel-установка сохраняет SQL и seed resources.
PostgreSQL принимает только шесть системных групп; пользователь принадлежит одной группе, организации задаются отдельными связями.
Это инфраструктурные ограничения. Серверная авторизация каждого бизнес-API будет добавлена до появления таких endpoint.
