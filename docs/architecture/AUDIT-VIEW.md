# Журнал аудита

Раздел `/audit`, API `GET /api/audit`. Это административный просмотр уже записанных
событий инфраструктуры, а не новая история всех будущих бизнес-процессов.

Доступ: существующее право `audit.view` со scope `all`, свежий MFA (5 минут)
и доступ ко всем действующим организациям. В текущей схеме события не имеют
обязательного organization_id, поэтому частичный межорганизационный просмотр
запрещён. Операционное право `audit.operational.view` не предоставляет доступ.
Права и контекст проверяются на каждом запросе, в том числе на следующей странице.

Возвращаются только id, время, UUID исполнителя, известный тип и фиксированное
название события, безопасный идентификатор объекта. Имена исполнителей не
подставляются: UUID не меняет значение после переименования учётной записи.
Для системных и неаутентифицированных событий исполнитель может отсутствовать.
Поле detail вообще не читается SQL-запросом; причины, before/after, полные КМ,
содержимое файлов, секреты и внутренний throttle key неудачного входа не выдаются.
UUID объекта и фиксированные group/system/backup разрешены только для известных
типов; у неизвестного типа скрыты и raw action, и объект. Тексты в UI выводятся
через textContent. Ответы имеют Cache-Control: no-store.

Фильтры API:

| Параметр | Значение |
|---|---|
| action | Один из ключей actions в ответе; иначе 422 |
| actor_id | UUID исполнителя |
| since, until | ISO datetime с часовым поясом, включительные границы |
| before_id | Положительный bigint, строго меньше указанного id |

Период проверяется на корректный порядок. Даты интерфейса вводятся в часовом поясе
браузера и передаются как UTC. Окончание в 12:00 означает именно 12:00:00,
а не всю минуту или весь день.

Сортировка по id DESC, 25 строк и один дополнительный lookahead; next_before_id
указывает границу следующей страницы либо null. Вставки с большим id не сдвигают
следующую страницу и появляются после «Обновить журнал». Это просмотр живого
журнала, не транзакционный snapshot: поздний commit транзакции, получившей меньший
sequence id, может появиться при следующем обновлении. Точный общий count не
вычисляется, экспорт и автопросмотр деталей не реализованы. Просмотр не добавляет
новое событие в журнал и не меняет append-only защиту БД.

Интерфейс: фильтр типа, UUID исполнителя, период, сброс, обновление, «Назад/Далее»;
пустое состояние, очистка старых строк при загрузке/ошибке/MFA, ручной повтор после
подтверждения. Отзыв права и изменение доступных организаций обрабатываются при
обновлении сессии; поздние ответы после выхода из раздела отсекаются. На узком
экране прокручивается таблица, а не вся страница. Светлая и тёмная темы используют
общие токены оформления.

Проверки: unit-тесты проекции, PostgreSQL для фильтров/границ/пагинации/приватности/
MFA/RBAC/global scope, Chromium для живого API, тем, 390 px, сети, пагинации,
пустого результата, подтверждения и отзыва права. Продуктивные интеграции и
CHECKPOINT этим срезом не активируются.
