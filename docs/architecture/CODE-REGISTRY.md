# Реестр кодов и этикеток

Дата: 25.10.2026. Проектное решение, если явно не указано иное.


Код идентифицируется КИ; полный payload хранится неизменяемыми версиями bytea, включая GS и криптографическую часть.
Сохранять исходный scanner input, результат нормализации, версию профиля и причины исправлений.
Строгие байты СУЗ не проходят scanner auto-fix. Нормализация не должна угадывать неоднозначные символы.
Последняя подтверждённая версия этикетки определяет данные для перепечати; если её нет — выдавать понятный блокер.
Фактическое количество ЧЗ после разделения и AI30 на старой физической этикетке могут различаться: хранить обе величины с датами.
Повторный скан того же КИ с другим full payload не подменяет сохранённый код; это конфликт, требующий разбора.
История связывает накладную, АТК/версию, задания склада, резервы, split, label и внешние операции.
Общий реестр ТСД не доступен, но разрешённая проверка возвращает необходимые сведения по отсканированному КМ.
