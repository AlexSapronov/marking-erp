# Сбор файлов читающего пилота НК

25.10.2026. Команда для оператора изолированного пилота, Ubuntu/Linux, Python3.12.
Использует [транспорт PR11](NK-READ-TRANSPORT.md) и формат
[офлайн-проверки PR10](../audit/NK-READ-CONTRACT.md). Автоматического запуска из ERP нет.

## Запуск

Установить проект в venv. Родительская папка должна уже существовать и быть доступна
оператору. Выходная папка создаётся новой; существующую папку команда не использует.
Пример первого запуска с одной страницей:

```bash
marking-erp-nk-pilot \
  --environment sandbox \
  --from-date '2026-10-01 00:00:00' \
  --to-date '2026-10-25 00:00:00' \
  --output /var/lib/marking-erp/nk-pilots/pilot-001 \
  --max-pages 1
```

Среда обязательна, production выбирается только явно. Команда запрашивает **токен
ГИС МТ**, не API KEY НК, скрытым вводом в TTY. Параметра --token и чтения токена
из environment/файлов нет; небезопасный fallback getpass с видимым вводом запрещён.
Команда не получает и не обновляет токен сама. Токен не записывается как конфигурация
или заголовок в файлы пилота; raw ответы остаются чувствительными данными внешнего источника.

По умолчанию читается максимум одна страница. Для расширенного пилота указать
--max-pages от1 до400; общий предел сохранённых тел —64MiB, параметр --max-bytes
допускает до256MiB. Лимит сохранения проверяется до записи файла; превышающий его
ответ к этому моменту уже мог быть получен транспортом. Разделения времени при413 нет.
Паузы/повторы/квоты наследуются от транспорта; обходить cooldown новым запуском нельзя.

## Файлы и результат

Папка0700, файлы0600; запись через открытый directory fd, без symlink в компонентах
пути и без перезаписи старого запуска. Путь абсолютный, вне каталога проекта/пакета;
родителя команда не создаёт. Папку не следует размещать в каталогах, публикуемых веб-сервером.
JSON metadata обновляются атомарной заменой с fsync; raw файлы создаются только один раз.

- list-OFFSET.json/details-OFFSET.json — исходные байты HTTP200, принятые транспортом.
  Они сохраняются до проверки JSON/состава, чтобы неожиданный контракт можно было исследовать.
- manifest.json — только полностью проверенные пары. Начальный пустой manifest
  создаётся до первого запроса. Он совместим с marking-erp-nk-check.
- run.json — выбранная среда, UTC-время, бюджеты, SHA256/размер/время получения тел,
  итоговое состояние и безопасные коды ошибок. URL/заголовки запросов сюда не входят.
  Времена и среда записаны локально; это не удостоверение владельца карточек или аккаунта НК.

stdout содержит только итоговые счётчики/ограничения и статические ошибки, без raw карточек.
Коды завершения:0 — complete;2 — page_limit;1 — failed или ошибка запуска;130 — interrupted.
При отказе сохраняются предыдущий manifest и уже записанные тела, включая неподтверждённую
последнюю пару. Отказы HTTP, сжатые/слишком большие тела и прерванные сетевые ответы
не сохраняются как полные тела. На дисковой ошибке/kill/power loss возможны файлы без
receipt и state=in_progress; они не означают успешный пилот. Manifest и run могут
расходиться по последнему checkpoint при аварии; проверять manifest отдельно.

```bash
marking-erp-nk-check --manifest /var/lib/marking-erp/nk-pilots/pilot-001/manifest.json
```

Офлайн-проверка может вернуть2 для корректно сохранённого, но неполного обхода.
Она не анализирует raw файлы, не включённые в manifest. run.json следует читать отдельно,
чтобы видеть причину остановки и retry_after. Каталог пилота закрытый, без встроенного
шифрования; не загружать реальные ответы в git или публичные артефакты CI.

Автоматического resume/склеивания запусков нет: меняющийся удалённый каталог и истечение
токена требуют нового контролируемого обхода. Файлы не импортируются в ERP, статусы/PN
не подтверждаются, контракты/worker не активируются. Полный контракт, I-001 и CHECKPOINT
остаются открытыми до рассмотрения реальных свидетельств и обязательных сценариев пилота.

## Проверки реализации

Синтетические тесты без внешней сети: полный/пустой/частичный обход, несколько страниц,
неверный HTTP200 контракт,403, бюджет байтов, Ctrl+C, сбой атомарного commit manifest,
права файлов, symlink/старый каталог, скрытый ввод/TTY и коды завершения CLI.
Успешный mock-запуск не является продуктивным пилотом.
