# Административное состояние системы

25.10.2026. Раздел /system и API GET /api/system/status. Это ручной просмотр
проверок инфраструктуры текущего процесса, не включение интеграций и не центр повторной отправки.

Доступ — system.diagnostics.view со scope=all, административный вход/MFA и свежее
подтверждение до5мин. По умолчанию право есть только у администратора. Дополнительно
нужен доступ ко всем действующим организациям: диагностика касается всей инсталляции.
Ограниченный администратор получает403 до запуска глобальных проверок.
Shell /system общедоступен как остальные HTML-shell, но не содержит защищённых данных.

## Экран

В меню появляется «Состояние системы». Кнопка «Обновить проверки» выполняет один GET;
автоматического опроса диагностики нет. Экран показывает проверенный SHA сборки,
ожидаемую схему и время получения результата, затем десять проверок:
отдельный пользователь сервиса, HTTPS/cookie, SHA релиза, приватное хранилище,
наличие ключа MFA, схема, runtime-роль БД, seed, включённый администратор/MFA,
расшифровка сохранённых MFA. Используется тот же инспектор, что в service check.

Результаты: «Пройдено», «Требует внимания», «Не проверено». Не выполненная из-за
предыдущей ошибки проверка не становится успешной. Даже при полном техническом
успехе подключения и бизнес-операции не объявляются готовыми.
В тестовой среде HTTP/миграционный owner/неподготовленный каталог закономерно дают
замечания; UI не подменяет эти результаты положительными.

Отдельный блок описывает текущее состояние поставляемого кода: НК — инструменты
пилота, ЧЗ/СУЗ — адаптеры не подключены, ГОСТ-подписант — нужен валидатор,
S55/S45 — нужен реальный пилот. Backup/restore реализованы, но расписание/offsite
и фактическое наличие свежей копии не проверяются этим экраном.
Внешних HTTP-запросов, поиска файлов backup, подключения к ПК подписанта или ТСД нет.
Неизвестное состояние компонента отображается как «Не проверено».

## Безопасность и ограничения

Данные результата проходят whitelist: только boolean/null десяти проверок, SHA
строго40 hex-символов, версия схемы из пакета, время и фиксированные статусы компонентов.
DSN, ключи, ciphertext, реальные пути, имена пользователей, идентификаторы организаций
и ошибки драйвера не возвращаются. Данные не сохраняются в localStorage; ответ no-store.
Значения UI вставляются textContent. Инспектор работает в отдельной read-only
транзакции, файловая проверка ничего не создаёт; endpoint не запускает seed/migrate/grant.

Проверки конфигурации HTTPS не являются TLS-handshake или проверкой доверия рабочего ПК.
Нет проверки сетевого периметра/свободного места/offsite. Состояние роли и схемы
может измениться после запроса: результат снабжён временем, не является durable разрешением.
Для запуска/проверки целевой VM остаётся [инструкция Ubuntu](UBUNTU-PILOT.md).

Истёкшее подтверждение даёт403/reauth_required: прежний отчёт убирается, предлагается
подтвердить доступ и вручную обновить проверки. Подтверждение не повторяет запрос молча.
При сетевой ошибке старые карточки также убираются. При обновлении сессии и отзыве
права меню/отчёт закрываются; при изменении организаций данные перечитываются.
Поколения запросов не позволяют позднему ответу восстановить закрытую страницу.

## Проверки реализации

Unit: whitelist секретов/типов и отсутствие ложного ready при unknown/failed.
PostgreSQL:401/403 до инспектора, пять неадминистративных групп, глобальный org-scope,
реальные результаты, no-store, отсутствие новых audit-записей от просмотра,
истёкшая MFA/отзыв права и неверный ключ без утечки.
Chromium: светлая/тёмная тема,390px, реальные проверки, offline/retry,
MFA с ручным обновлением и отзыв права на открытом экране. Mock-ответов API в UI-тестах нет.
